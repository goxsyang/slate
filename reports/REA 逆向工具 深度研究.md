# REA 拆掉的是逆向门槛，不是软件护城河

REA（Reverse Engineer Anything，`github.com/morluto/rea`，npm 包名 `rea-agents`）是真实存在、以 MIT 授权开源的本地工具。它自己不带 AI 模型，也没有发明新的反编译技术。它做的是把 Ghidra、Hopper、IDA 等现成逆向引擎，加上自带的 JS/Electron/.NET 静态解析器，通过 MCP 协议包装成 170 到 200 多个工具，交给 Claude Code、Codex、Cursor 等 AI 代理调用。逐条核对之后，Facebook 帖子里的**事实性说法几乎都能找到一手出处**：星数（GitHub 页面 2026-10-15 13:25 UTC 显示约 26.0 万，13:54 UTC 复核为 26.06 万，帖子说"超过 22 万"其实还保守了）、MIT 授权、引擎和代理清单、目标类型、Windows 计算器和 DX-Ball 两个示范的数字、官方 FAQ 里关于数据的说法，都对得上。问题在于帖子**删掉了会改变含义的语境**。计算器示范按官方自己的证据档，函数是"分析师辅助"选出来的，解释的也是微软早已开源、写进单元测试的既定设计；DX-Ball 的"3,205 个测试、63 字节一致"只针对一个 23 条指令的小函数，验证是 REA 第二号贡献者自己的重建项目做的；"老手称炒作"则只是一位专家转发时写的一个词。业界比较一致的判断是：REA 的新意在**整合、打包和证据纪律**，把"会逆向的人才能让 AI 帮忙逆向"的门槛大幅拉低。它没有突破加壳、虚拟化保护、服务器端逻辑这些硬边界，官方文件自己也承认这些限制，或者明说刻意不做。现实风险有三类：分析结果（包括反编译代码和程序里内嵌的密钥）会流向模型商；它不是沙箱，部分工具会以用户权限执行目标程序；法律上，"分析"、"规避保护"、"复制表达"是三条不同的线。至于帖子结尾的问题，有依据的回答是：REA 主要"解放"的是对未加保护的客户端软件的**理解**，同时大幅降低了**模仿功能**的成本；直接"抄代码"在各主要法域仍然是侵权，而且 AI 读过反编译代码之后再"重写"，很难主张净室（clean room）开发。

## 一个 npm 包，把现成逆向引擎接进 AI 代理

REA 的形态很简单：一个 npm 包（当前发布版 **`rea-agents` 6.5.0，2026-10-14 发布**），同时是本地 stdio MCP 服务器（`rea-agents mcp`）和命令行工具（`rea`），两者共用同一套工作流，运行需要 Node.js 22.19+、24.11+ 或 26+（[package.json](https://github.com/morluto/rea/blob/b2257653ca74e1013553d5bd916a0ef85a3c7678/package.json)、[server.json](https://github.com/morluto/rea/blob/b2257653ca74e1013553d5bd916a0ef85a3c7678/server.json)、[npm registry](https://registry.npmjs.org/rea-agents)）。官方自述是："REA connects your agent to tools for inspecting native binaries, JavaScript and Electron apps, .NET assemblies, and websites… Analysis runs locally"（REA 把你的代理接到检查原生二进制、JS/Electron 应用、.NET 程序集和网站的工具上，分析在本机运行）（[README.md:63](https://github.com/morluto/rea/blob/b2257653ca74e1013553d5bd916a0ef85a3c7678/README.md#L63)）。执行 `npx rea-agents setup` 会先展示变更计划，用户批准后才把一个**锁定到具体版本**的 MCP 注册写进所选代理的配置，同时安装一份名为 `reverse-engineer-anything` 的工作流技能，并为原配置留 `.rea.backup` 备份；Hopper 演示版可以另行批准安装（[docs/installation.md](https://github.com/morluto/rea/blob/b2257653ca74e1013553d5bd916a0ef85a3c7678/docs/installation.md#L14)）。可自动配置的客户端，文档表格列了 **24 个**，包括 Claude Code、Claude Desktop、Codex、Cursor、Gemini CLI、Windsurf、GitHub Copilot CLI、VS Code、Qwen Code、Kimi Code、DeepSeek Harness 等（[docs/installation.md:454](https://github.com/morluto/rea/blob/b2257653ca74e1013553d5bd916a0ef85a3c7678/docs/installation.md#L454)）。代码里的定义有 25 个，多出来的是要手动接的 Grok Bot（[SupportedClients.ts:485](https://github.com/morluto/rea/blob/b2257653ca74e1013553d5bd916a0ef85a3c7678/src/application/SupportedClients.ts#L485)）。官网 FAQ 只列了 14 个，属于文档滞后。值得注意的是，依赖清单里**没有任何模型商 SDK**，"AI"那部分完全是用户自己的代理。

真正干活的是底层引擎。原生程序方面：Hopper 通过 `--python` 启动参数注入一段 Python 桥接脚本，走带随机令牌认证的 Unix socket 通信；Ghidra 以 `analyzeHeadless` 无头模式运行，在临时隔离的项目里执行 REA 的 Java `HeadlessScript`，经验证的组合是 Ghidra 12.1.4 加 JDK 21；IDA 则是代理第三方的 `mrexodia/ida-pro-mcp`（只支持 IDA Pro），另有实验性的 IDA Free 插件路线，而 IDA Free 的云端反编译器需要联网（[bridge/hopper_bridge.py](https://github.com/morluto/rea/blob/b2257653ca74e1013553d5bd916a0ef85a3c7678/bridge/hopper_bridge.py#L1)、[docs/ghidra-provider.md](https://github.com/morluto/rea/blob/b2257653ca74e1013553d5bd916a0ef85a3c7678/docs/ghidra-provider.md#L3)、[docs/ida-provider.md](https://github.com/morluto/rea/blob/b2257653ca74e1013553d5bd916a0ef85a3c7678/docs/ida-provider.md#L3)）。此外还可以接 Apache-2.0 的 Kuna 反编译器、objdump 和 Rizin。非原生目标用的是 REA 自己写的解析器：JS/Electron 靠 Babel 解析器、ASAR 读取器和 source map 解码；.NET 是自研的 TypeScript 元数据/CIL 读取器，**给出的是元数据和 IL 指令，不是 C# 反编译**；"网站"是通过 Chrome DevTools Protocol 附着到用户自己的 Chrome 浏览器上被动观察（[docs/managed-code-analysis.md:3](https://github.com/morluto/rea/blob/b2257653ca74e1013553d5bd916a0ef85a3c7678/docs/managed-code-analysis.md#L3)、[docs/browser-observation.md:9](https://github.com/morluto/rea/blob/b2257653ca74e1013553d5bd916a0ef85a3c7678/docs/browser-observation.md#L9)）。长尾目标还有 Android（JADX、apktool、ADB、JEB）、固件（Binwalk/Unblob）、Go、Rust、WASM、EVM、SQLite、抓包、逻辑分析仪信号和 Frida 动态插桩，每一种都要用户自备对应工具（[README.md:169-193](https://github.com/morluto/rea/blob/b2257653ca74e1013553d5bd916a0ef85a3c7678/README.md#L169)）。每个会话只绑定一个深度分析引擎，引擎失败时不会自动换另一个。

各方报的工具数量不一样，这里统一说明。官方文档写的是：主分支提交 04089d5be 时有 **172 个工具**，在客户端不做延迟加载时，工具定义约 496 KB，**约合 12 万 token**（[docs/client-configuration.md:104](https://github.com/morluto/rea/blob/b2257653ca74e1013553d5bd916a0ef85a3c7678/docs/client-configuration.md#L104)）。6.5.0 开发期间的一个 PR 里，Kimi Code 实测发现 173 个。审计当前 HEAD 代码的 `TOOL_EFFECTS` 效果清单（每个公开工具都必须登记），一共 **207 个**（[toolEffects.ts:55](https://github.com/morluto/rea/blob/b2257653ca74e1013553d5bd916a0ef85a3c7678/src/contracts/toolEffects.ts#L55)）。第三方文章里的"133 个""126+"都是更早版本的数字。比较稳妥的说法是：开发主线已到 207 个，已发布的 6.5.0 应介于 173 和 207 之间（6.5.0 的更新说明新增了 SQLite、抓包、WASM、Electron fuses 等多类工具，确切数字本研究无法运行核实），外加 6 个 MCP 引导提示（[docs/mcp-prompts.md](https://github.com/morluto/rea/blob/b2257653ca74e1013553d5bd916a0ef85a3c7678/docs/mcp-prompts.md#L3)）。REA 和同类工具在设计上最大的不同，是每个工具都返回一条带内容哈希 ID 的 **Evidence 记录**，里面有标准化结果、局限和未知项，可以导出、比对，也能接入"重建义务账本"（[docs/mcp-contracts.md:11](https://github.com/morluto/rea/blob/b2257653ca74e1013553d5bd916a0ef85a3c7678/docs/mcp-contracts.md#L11)）。这个账本只负责记账，REA 并**不自带**编译器比对或字节匹配工具。

项目背后是笔名开发者 **morluto**：个人账号，约 6.2k 关注者，看不到公司、融资或收费产品；核心协作者是 N0zoM1z0 和 kaoru0822-kitauji（[GitHub 个人页](https://github.com/morluto)、[npm registry](https://registry.npmjs.org/rea-agents)）。代码量很大，按对[仓库](https://github.com/morluto/rea/tree/b2257653ca74e1013553d5bd916a0ef85a3c7678)的行数统计，非测试 TypeScript 约 31 万行，测试约 39 万行，而且大量由 AI 编码代理参与编写：6.5.0 发布区间的 893 个提交里，有 109 个把 Claude Opus 5.5 列为作者之一，提交说明里的"Co-authored-by: Claude Opus 5.5"字样累计约 280 次（[6.5.0.contributions.json](https://github.com/morluto/rea/blob/b2257653ca74e1013553d5bd916a0ef85a3c7678/docs/releases/6.5.0.contributions.json)）。时间线方面，仓库据二手资料创建于 2026-04-14（[pasqualepillitteri.it](https://pasqualepillitteri.it/en/news/23845/rea-reverse-engineer-anything-github-true-false)，未经 API 核实）；npm 首发是 **2026-07-12**；8 月 9 日到 10 月 3 日之间停发了约 8 周；10 月 3 日恢复发版，10 月 5 日前后登上 GitHub Trending，到 10 月 14 日已从 3.2.0 一路发到 6.5.0（12 天内 12 个版本，[npm registry](https://registry.npmjs.org/rea-agents)）。三个月里出了 **6 个主版本**，接口变化很快。

使用成本方面，REA 本身免费。原生分析最省钱的组合是免费的 Ghidra 加 JDK 21。走 REA 主要 IDA 路线需要 **IDA Pro 授权**；Hopper 和 JEB 是商业软件，JEB 的 EULA 还限制公开反编译结果。官方明说："REA grants no tool license, key, or activation entitlement"（REA 不提供任何工具授权、密钥或激活权利）（[README.md:389-395](https://github.com/morluto/rea/blob/b2257653ca74e1013553d5bd916a0ef85a3c7678/README.md#L389)）。真正的边际成本是模型订阅和 token。官方东方 Project 重建案例的证据档写明，背后用的是 GPT-6-Astra 等顶级模型的高强度推理（[reverse-engineering-models.md:19-33](https://github.com/morluto/rea/blob/b2257653ca74e1013553d5bd916a0ef85a3c7678/website/evidence/reverse-engineering-models.md#L19)）。

## 两个官方示范都是真的，但都比帖子讲的小得多

**Windows 计算器是首页的教学例子，不是正式案例。** README 列出的正式案例只有 DX-Ball、Notion、TH04 三个，官网案例索引是五个（再加上 Aegis 和一道 CTF 题），计算器都不在其中，只出现在首页的"Example 02"（[README.md:216-247](https://github.com/morluto/rea/blob/b2257653ca74e1013553d5bd916a0ef85a3c7678/README.md#L216)）。证据档写明：2026 年 10 月 9 日用 REA 4.1.0 检查了 Windows 计算器 11.2508.4.0 x64；`calc.exe` 只是一个跳转到 `ms-calculator:` 的启动器，真正的计算在 `CalcViewModel.dll` 的 `0x1801245d0` 函数里（10,656 字节），其中 `case 0x76` 把运算符和 `0x5c`、`0x5b` 比较，并构造常数 100（[calculator-and-dino.md:16-36](https://github.com/morluto/rea/blob/b2257653ca74e1013553d5bd916a0ef85a3c7678/website/evidence/calculator-and-dino.md#L16)）。同一份证据档也自曝了帖子没提的三个前提，原文是："The binary is stripped. A local instruction scan located candidates using operator IDs and the constant 100; REA then produced the complete function dossier. **Function selection was analyst-assisted.** The illustrative agent prompt is not a recording of an autonomous end-to-end discovery."（二进制已去符号；先用本地指令扫描按运算符 ID 和常数 100 找出候选，REA 再生成完整的函数档案。函数是分析师辅助选出的，示意提示词不是自主端到端发现的录像。）它还写了："no completed Windows GUI input result is claimed"（不声称完成了 Windows 界面实测）（[calculator-and-dino.md:48-51、71-73](https://github.com/morluto/rea/blob/b2257653ca74e1013553d5bd916a0ef85a3c7678/website/evidence/calculator-and-dino.md#L48)）。

更关键的是，"为什么等于 220"从来不是秘密。微软 2019 年以 MIT 授权开源了计算器，`scifunc.cpp` 的 `case IDC_PERCENT` 里有注释写明规则：遇到乘除时 Y% 当作 Y/100，遇到加减时当作 X×Y/100。运算符常量 `IDC_DIV 91`、`IDC_MUL 92`、`IDC_PERCENT 118` 换成十六进制，正好是 REA 档案里看到的 0x5b、0x5c、0x76（[scifunc.cpp:98-111](https://github.com/microsoft/calculator/blob/d125246a4e19842ce1332e6c7839cf0e110027d8/src/CalcManager/CEngine/scifunc.cpp#L98-L111)）。微软自己的单元测试里也有"50 + 20% = 60"这一条（[CalculatorManagerTest.cpp:350-370](https://github.com/microsoft/calculator/blob/d125246a4e19842ce1332e6c7839cf0e110027d8/src/CalculatorUnitTests/CalculatorManagerTest.cpp#L350-L370)）。Raymond Chen 早在 2008 年就解释过，这是仿照廉价袖珍计算器的设计（[The Old New Thing](https://devblogs.microsoft.com/oldnewthing/20080110-00/?p=23853)，内容来自检索摘要）。所以这个示范能证明 REA 可以从去符号的 x64 DLL 里定位到相关分支，**不能证明它能自主发现隐藏逻辑**；一个模型完全可能直接凭训练数据答出"为什么是 220"。部分中文媒体用"微软十年没修的 Bug"做标题，更是误导：这不是 bug。据检索摘要，那个"十年"的故事指的是另一位用户的远程桌面问题（[blog.eimoon.com](https://blog.eimoon.com/p/rea-reverse-engineer-anything/)）。

**DX-Ball 的数字全对，但描述的是一个 23 条指令的小函数。** 目标是 158,208 字节的 `DXBALL.EXE`，函数地址 `0x406400` 到 `0x40643e`，正好 63 字节，分析环境是 REA 4.1.0 加 Ghidra 12.1.4（[dx-ball-sound-pan.md:9-12](https://github.com/morluto/rea/blob/b2257653ca74e1013553d5bd916a0ef85a3c7678/website/evidence/dx-ball-sound-pan.md#L9)）。还原出来的 C 代码只有一行算式，**`(1.5625·x − 500)·scale` 再转成整数**；调用者传入的是 `x*30+20`，也就是砖块的横向屏幕位置。缩放值为 1 时，左缘返回 −500，中央返回 0，右缘返回 +500（[gameplay.c:41-56](https://github.com/N0zoM1z0/dx-ball/blob/a55dca27ec0a07018c1b2c95ae2be027f7d8c3c4/src/gameplay.c#L41)）。"3,205 种情况"就是 0 到 640 的每个整数位置，乘上 0、0.5、1、20、−1 五个缩放值（641×5），原版 x86 函数在 Unicorn CPU 模拟器里执行后逐一比对（[test_gameplay_differential.py](https://github.com/N0zoM1z0/dx-ball/blob/a55dca27ec0a07018c1b2c95ae2be027f7d8c3c4/tests/test_gameplay_differential.py)）。"63 字节一模一样"是指用固定版本的 Visual C++ 4.0、以不优化的 `/Od` 参数重新编译，套用 4 处经审核的重定位（两个 double 常数、缩放变量、`__ftol`）后，整个函数逐字节相同（[match-units.toml:27-38](https://github.com/N0zoM1z0/dx-ball/blob/a55dca27ec0a07018c1b2c95ae2be027f7d8c3c4/config/match-units.toml)、[BUILD_MATCHING.md](https://github.com/N0zoM1z0/dx-ball/blob/a55dca27ec0a07018c1b2c95ae2be027f7d8c3c4/docs/BUILD_MATCHING.md)）。帖子漏掉了三件事。第一，**测试和比对都不是 REA 做的**，官网原话是："REA supplies the instructions, callers and data reads; the reconstruction project implements and tests the result."（REA 只提供指令、调用者和数据读取，实现和测试由重建项目负责）（[showcase/dx-ball](https://github.com/morluto/rea/blob/b2257653ca74e1013553d5bd916a0ef85a3c7678/website/public/showcase/dx-ball/index.html)）。第二，重建项目的作者 N0zoM1z0 是 **REA 第二号贡献者**，所以这不是独立第三方的验证（[people.json:13-17](https://github.com/morluto/rea/blob/b2257653ca74e1013553d5bd916a0ef85a3c7678/website/public/contributors/people.json#L13)）。第三，**Ghidra 第一版反编译结果是错的**，输出成了 `FUN_00406400(void)`，漏掉了栈上的参数和 x87 浮点运算；代理对照指令视图、调用者和常量字节才发现问题（[dx-ball-sound-pan.md:36-38](https://github.com/morluto/rea/blob/b2257653ca74e1013553d5bd916a0ef85a3c7678/website/evidence/dx-ball-sound-pan.md#L36)）。这一点恰恰是整个示范里最有价值的地方，帖子却没提。

放到"匹配式反编译"（matching decomp）社区的标准里看，这只是起步难度。Super Mario 64 早已有完整、可逐字节重建的反编译项目（[n64decomp/sm64](https://github.com/n64decomp/sm64/blob/master/README.md)）；2025 年底起，Chris Lewis 没用 REA，靠 Claude Code 等编码代理把《Snowboard Kids 2》的匹配率从约 25% 推到约 75%，2026 年 5 月又宣布整部游戏 100% 匹配（后期还用了 GLM 和 Codex）（[Simon Willison](https://simonwillison.net/2025/Dec/6/one-shot-decompilation/)、[Chris Lewis 长尾篇](https://blog.chrislewis.au/the-long-tail-of-llm-assisted-decompilation/)、[Chris Lewis 完成公告](https://blog.chrislewis.au/snowboard-kids-2-is-100-decompiled/)，均为检索摘要）。不优化、无分支、常数已知的 23 条指令函数，属于最容易匹配的一类。在示范采用的 10 月 7 日检查点，整个 DX-Ball 重建有 528 个候选函数，其中 55 个有源码、33 个逐字节一致，游戏仍不能玩（[PROGRESS.md @a55dca27](https://github.com/N0zoM1z0/dx-ball/blob/a55dca27ec0a07018c1b2c95ae2be027f7d8c3c4/docs/PROGRESS.md)）。到 10 月 15 日，HEAD 已有 360 多个条目逐字节一致（当天两次读取分别为 361 和 362，含运行库和编译器生成的代码），作者写的是"Exact reconstruction is in progress"（[PROGRESS.md HEAD](https://github.com/N0zoM1z0/dx-ball/blob/HEAD/docs/PROGRESS.md)）。比起 63 字节，这个进度才更能说明"代理加 REA"的实际产能。"55 个、33 个"这组数字也写在 REA 自己的官网案例页上（[showcase/dx-ball](https://github.com/morluto/rea/blob/b2257653ca74e1013553d5bd916a0ef85a3c7678/website/public/showcase/dx-ball/index.html)）。还要注意，官方案例普遍挑了有标准答案可对照的目标（开源的 Aegis、公开题解的 CTF、作者自己的重建项目）；唯一的闭源商业目标 Notion 是没有混淆的 JavaScript，而 .NET、固件、加壳程序都没有任何官方案例（[showcase 索引](https://github.com/morluto/rea/blob/b2257653ca74e1013553d5bd916a0ef85a3c7678/website/public/showcase/index.html)）。

## 专家嫌它"炒作"的理由：旧技术、新包装、低门槛

"炒作"这个说法可以追到**极客公园 2026-10-12 的《一周 10 万星，AI「逆向一切」，但大家不要过于兴奋》**，新浪、凤凰、快科技、17173、投资界都转载过（[极客公园](https://www.geekpark.net/news/372263)、[新浪科技](https://finance.sina.com.cn/tech/roll/2026-10-12/doc-iniuyxuw0423270.shtml)、[17173](https://news.17173.com/content/10132026/020528855.shtml)）。帖子里"老手称炒作、加壳难拆、服务器逻辑碰不到、数据交给模型商"这四点，和这篇报道几乎一一对应，帖子很可能直接或间接引自它。据报道，《Practical Reverse Engineering》合著者 **Elias Bachaalany**（据称曾任职 IDA 开发商 Hex-Rays，未独立核实）转发 REA 推介时只写了一个词"Hype"，随后列出 GhidraMCP、IDA Pro MCP 等早已存在的工具；36 氪、荷兰 AI Insider、KuCoin 快讯也有相同说法（[36Kr](https://www.36kr.com/p/4022845063647361)、[AI Insider](https://aiinsider.nl/nieuws/rea-reverse-engineer-anything-github-ai-agents/)、[KuCoin](https://www.kucoin.com/news/flash/ai-reverse-engineering-tool-rea-surges-by-100-000-stars-in-a-week-sparking-legal-and-technical-controversies)）。**这条 X 原帖本研究没能直接核实**，所有内容都来自检索摘要。公开具名的批评者基本只有他一人，"逆向圈老手们"不能理解为圈内共识。就连同一篇报道也承认："REA 真正新的地方，其实还是在被大幅降低的逆向门槛"。

社区反应是好奇和怀疑参半。Hacker News 主讨论串据报道有约 760 到 805 分、三百多条评论，各来源数字不一，原帖未能读取；据报道，最受认同的质疑是"这比直接让 Claude 去装 Ghidra 好在哪里"（[HN 50028275](https://news.ycombinator.com/item?id=50028275)）。daily.dev 的汇总给出的情绪分布是 45% 正面、30% 褒贬参半、25% 怀疑（[daily.dev](https://daily.dev/posts/rea-hit-120k-stars-in-a-week-and-nobody-s-asking-permission-9pxzfdci8)，检索摘要）。中文社区以"拆水分"式的长文为主：linux.do 有作者实测 6.4.0 后认为，JS/Electron 语义引擎约 4 万行原创代码是"干货"，Go 解析器只有 112 行、主要读嵌入的 buildinfo，.NET 分析上限约 2,000 个方法，Windows 上 18 项操作有 10 项返回 `unsupported_host`；他的结论是 REA 适合当"给 Agent 用的逆向工具接口层"（[linux.do](https://linux.do/t/topic/3023859)）。掘金的评论一针见血："以前想让 AI 帮你逆向，你得先是个会逆向的人"（[掘金](https://juejin.cn/post/7695958498477211675)）。

**独立实测（以下全部来自检索摘要，未读全文）** 大体印证了"静态 JS/Electron 和 .NET 最成熟、原生分析很依赖外部引擎、真实打包代码的召回率不足"。MindStudio 让 REA 和普通代理对比重建 Mac Preview 的功能，结论是 REA "wasn't dramatically better or categorically more capable"（没有显著更好，也没有质的提升），而且更慢（[MindStudio](https://www.mindstudio.ai/blog/reverse-engineer-anything-mcp)）。一篇 DEV 实测拿 Electron Fiddle 做目标，标题是"The analysis counted zero bridges. The app exposes 51 methods."（分析数出零个桥接，实际暴露了 51 个方法），原因是 Webpack 的别名让 REA 无法证明那是 Electron API（[DEV/ianwieds](https://dev.to/ianwieds/the-analysis-counted-zero-bridges-the-app-exposes-51-methods-25ok)）。另一篇拿 100 MB 的 Electron 应用测试，漏了两个 preload 文件（[DEV/ishank-dev](https://dev.to/ishank-dev/i-pointed-rea-at-a-100-mb-electron-app-heres-what-it-found-and-the-two-preload-files-it-missed-502p)）。.NET 测试约 1.5 秒就读出了方法、签名，还有**程序里内嵌的上传密钥**，作者称 REA 是"a coordinator rather than a decompiler"（协调者而非反编译器）（[DEV/nazecode](https://dev.to/nazecode/i-tried-rea-the-1-trending-repo-on-github-can-ai-really-reverse-engineer-a-net-app-4apo)）。把 20 MB 的 Rust 程序丢给 REA，没装引擎时直接返回 `provider_unavailable`（[DEV/shanhan_dev](https://dev.to/shanhan_dev/rea-claims-it-can-reverse-engineer-anything-and-pulled-120k-stars-in-a-week-so-i-handed-it-my-5bm2)）。GitHub issue 里，Windows 上 Ghidra 被硬性关闭（[#527](https://github.com/morluto/rea/issues/527)）、拒收 32 位 PE（[#806](https://github.com/morluto/rea/issues/806)）、Java 和 Ghidra 版本锁死（[#821](https://github.com/morluto/rea/issues/821)）、拒绝 linux/arm64 主机（[#1131](https://github.com/morluto/rea/issues/1131)）等问题都有记录；其中 32 位 PE 和 linux/arm64，按当前文档已在主分支补上支持，说明这类问题多出在早期版本（[windows-ghidra-p0.md](https://github.com/morluto/rea/blob/b2257653ca74e1013553d5bd916a0ef85a3c7678/docs/windows-ghidra-p0.md)、[installation.md:765](https://github.com/morluto/rea/blob/b2257653ca74e1013553d5bd916a0ef85a3c7678/docs/installation.md#L765)）。**本研究没找到任何独立测试成功拆开过商业加壳或虚拟化保护的程序。**

| **REA** | 编排层，覆盖 4 个以上原生后端，外加 JS/.NET/网页/Android/固件 | 统一词汇、Evidence 契约、24 个客户端一键配置 | 约 260k |

（星数为研究期间各仓库页面快照。）第三方研究仓库 ringozzt/rea-research 的总结很到位：REA 是"反编译器的 agent 化编排层"，"REA 赢的不是首创，而是广度+打包+证据契约"，而且"工具数本身不是壁垒"（[ringozzt/rea-research](https://github.com/ringozzt/rea-research)）。

真实局限可以分成"设计上不做"和"做了但不够好"两类。设计上不做的有：**脱壳和去虚拟化**，官方明说不整合"Purpose-built workflows to defeat commercial packing or code-virtualization protections"（专门对付商业加壳或代码虚拟化保护的工作流），只能分析另行准备好的脱壳副本（[CONTRIBUTING.md:127-131](https://github.com/morluto/rea/blob/b2257653ca74e1013553d5bd916a0ef85a3c7678/CONTRIBUTING.md#L127)、[ghidra-dos.md:150-151](https://github.com/morluto/rea/blob/b2257653ca74e1013553d5bd916a0ef85a3c7678/docs/ghidra-dos.md#L150)）；**服务器端逻辑**；以及 DRM、授权检查、反作弊的绕过。安全博主"轩辕之风"的说法是"没加壳的程序 AI 轻松拿下，轻度加壳也行，VMP 这类高强度虚拟化保护目前还啃不动"。据什么值得买转述，B 站一次实测里，开启 VMP 虚拟化之后，跑了 54 分钟宣告失败（[什么值得买](https://post.smzdm.com/p/arzr0k3g/)，二手）。linux.do 的作者也指出，REA"从不执行目标代码"的设计，碰到 JSVMP 就是硬伤。做了但不够好的有：Windows 支持仍属实验性；工具定义要占大量上下文；成功案例多是训练数据里可能已有的开源项目，容易高估能力（[MIT 科技评论中文版](https://www.mittrchina.com/news/detail/17086)）；反编译器本身会出错。至于"连动态调试都没有"的批评，说得也不完全准确：REA 有 gdb、Rizin 调试会话和 Frida 插桩工具，但没有 x64dbg 那样的 Windows 交互式调试器（[toolEffects.ts](https://github.com/morluto/rea/blob/b2257653ca74e1013553d5bd916a0ef85a3c7678/src/contracts/toolEffects.ts#L55)）。官方的免责声明说得最直白："Decompilation, reconstruction, heuristics, and AI-assisted analysis may be incomplete or incorrect"（反编译、重建、启发式和 AI 辅助分析都可能不完整或有错）（[DISCLAIMER.md:63-65](https://github.com/morluto/rea/blob/b2257653ca74e1013553d5bd916a0ef85a3c7678/DISCLAIMER.md#L63)）。

## 风险分三层：法律看行为，数据会外流，本机也不是沙箱

### 理解、规避、复制是三条不同的法律线

先说明：以下是一般信息，不是法律意见。台湾条文的逐字内容，本研究没能在全国法规资料库核对；美国和欧盟的条文与判例依研究者既有知识整理，并附权威出处。各主要法域有一个共同结构：**著作权保护表达，不保护思想、程序或操作方法**。台湾《著作权法》第 10 条之 1 明文如此（[全国法规资料库](https://law.moj.gov.tw/LawClass/LawAll.aspx?pcode=J0070017)）；欧盟法院在 SAS v World Programming 案（C-406/10，2012）中认定，程序的功能、编程语言和数据格式都不受保护（[SCL](https://www.scl.org/2436-sas-v-wpl-no-copyright-says-ecj/)）。所以，看懂计算器为什么得出 220，再自己写出同样的逻辑，原则上没有问题；把反编译出来的代码表达搬进自家产品，就有侵权风险。差别主要在三个问题上。

| 法域 | 为研究或互通性而反编译 | 规避技术保护措施 | EULA 禁止逆向条款的效力 |
|---|---|---|---|
| 台湾 | 没有明文许可，依第 65 条合理使用逐案判断；营业秘密法的"不正当方法"一般认为不包括还原工程 | 第 80 条之 2 第 3 项把"为进行还原工程者"列为例外，范围由主管机关认定要点限定；规避本身只负民事责任，提供破解工具或服务才有刑责（第 96 条之 1）（[第 80 条之 2](https://law.moj.gov.tw/LawClass/LawSingle.aspx?pcode=J0070017&flno=80-2)、[智慧局资料](https://www.tipo.gov.tw/wSite/public/Attachment/0/f1747972069582.pdf)） | 没有"约款无效"的明文，只能依民法第 247 条之 1（定型化契约显失公平）逐案争执；本研究没找到相关判决 |
| 美国 | Sega v. Accolade（1992）认定，为取得思想和功能要素而反组译可构成合理使用（[Justia](https://law.justia.com/cases/federal/appellate-courts/F2/977/1510/57786/)） | §1201(f) 互通性例外、§1201(j) 安全测试例外（[17 U.S.C. §1201](https://www.law.cornell.edu/uscode/text/17/1201)） | Bowers v. | 欧盟 | 指令 2009/24/EC 第 5(3) 条允许观察、研究、测试；第 6 条允许为互通性所必需的反编译（[Art. 6](https://www.legislation.gov.uk/eudr/2009/24/article/6)） | 第 6(2) 条：取得的信息不得用于开发表达上实质相似的程序 | 第 8 条：违反第 5(2)(3) 条或第 6 条的约款**无效**（[Art. 8](https://www.legislation.gov.uk/eudr/2009/24/article/8)） |

这张表能直接说明帖子"灰区"二字的含义：分析本身在多数地方有空间，但**规避保护、复制表达、违反授权合同**分别受不同规则约束；而且软件 EULA 常常约定外国（多为美国州法）为准据法，所以台湾或大陆用户实际面对的，可能是美国那套"合同优先"的风险。REA 官方的立场比帖子说的"只说"要具体：DISCLAIMER 列出的合法用途包括资安研究、恶意程序分析、漏洞研究和协调披露、CTF、教育、互通性、软件保存，以及审计你拥有或获准检查的软件；明确不支持的用途有 6 类，包括绕过 DRM、授权检查和反作弊，开发外挂，"copying proprietary software or reproducing its protected code and assets"（复制专有软件或重现其受保护的代码和素材），以及规避 AI 模型商的政策（[DISCLAIMER.md:5-19](https://github.com/morluto/rea/blob/b2257653ca74e1013553d5bd916a0ef85a3c7678/DISCLAIMER.md#L5)）。它还写明："Obtaining source-like output or an analysis report does not grant rights to the original program"（拿到类源码输出或分析报告，不代表取得原程序的任何权利）（[DISCLAIMER.md:68-71](https://github.com/morluto/rea/blob/b2257653ca74e1013553d5bd916a0ef85a3c7678/DISCLAIMER.md#L68)）。不过源码审计发现，这些**全是政策文字**：代码里没有任何识别或拒绝 DRM、反作弊目标的逻辑，执行靠的只是社区管理。法律评论还指出，"重建"没有对应的法定豁免（[极客公园](https://www.geekpark.net/news/372263)）；AI 代理一边读反编译代码一边"重写"，满足不了净室开发的隔离要求（[KuCoin](https://www.kucoin.com/news/flash/ai-reverse-engineering-tool-rea-surges-by-100-000-stars-in-a-week-sparking-legal-and-technical-controversies)）。REA 自己的文档也建议，要做净室分离，就得让实现环境在文件系统和网络上都碰不到 REA、目标程序和分析输出（[installation.md:163-165](https://github.com/morluto/rea/blob/b2257653ca74e1013553d5bd916a0ef85a3c7678/docs/installation.md#L163)）。风险最高的是整部作品的逐字节重建：REA 证据档记载，东方 Project TH08 的重建在 2026-08-30 发布了可玩的 64 位 Linux 版（[touhou-reconstruction-method.md:101-110](https://github.com/morluto/rea/blob/b2257653ca74e1013553d5bd916a0ef85a3c7678/website/evidence/touhou-reconstruction-method.md#L101)）。这已经不是"理解功能"，而是接近把整部作品的表达转译成另一种形式，在欧盟正好落进第 6(2) 条禁止的情形。这是推论，没有判例。

### "本机分析"不等于数据不出门

帖子对 FAQ 的转述准确，但实际流出的范围比"结果"二字大得多：代理请求到的**反编译代码、字符串、抓到的网络流量、文件内容**都会整段进入对话，再发给模型商。源码审计没有发现 REA 自身有遥测或分析 SDK，日志只写 stderr，REA 自己的外联仅限 Hopper 安装、手动执行 `rea update` 和本机回环连接。所以泄露风险几乎全在"代理加模型"这条通道上，再加上目标程序运行时自己产生的流量。以 Claude Code 为例：消费版（Free/Pro/Max）允许数据用于训练时，保留期为 **5 年**，不允许时为 30 天；Team、Enterprise 和 API 等商业条款默认不训练，标准保留 30 天，符合条件的企业账户可以申请零数据保留（ZDR）；另外，会话记录会以明文形式在本机 `~/.claude/projects/` 默认保存 30 天（[Claude Code 数据使用说明](https://code.claude.com/docs/en/data-usage)）。OpenAI 的个人方案（包括 Codex）可能用内容训练，可以选择退出，而 Codex 有单独的设置项；商业版和 API 默认不训练（[OpenAI 帮助中心](https://help.openai.com/en/articles/5722486-how-your-data-is-used-to-improve-model-performance)，检索摘要）。Cursor 取决于是否开启 Privacy Mode（[第三方整理](https://conductatlas.com/platform/cursor/cursor-data-use-privacy-overview/privacy-mode-zero-data-retention/)，二手）。极客公园特别提醒：如果拆的是客户软件或受保密协议约束的软件，"这一步本身可能违约"（[凤凰科技](https://tech.ifeng.com/c/8x8ubG3BSNJ)）。使用政策层面，Anthropic 的可接受使用政策禁止未经系统所有人授权去发现或利用漏洞、绕过安全控制，但明文写着"does not prohibit security research, testing, or tool development conducted on systems you own or operate, with the authorization of the system owner, or within the scope of an authorized bug bounty program or vulnerability disclosure policy, provided the activity complies with applicable law"（不禁止在你拥有或运营的系统上、经系统所有人授权、或在授权的漏洞赏金或漏洞披露计划范围内做安全研究、测试或工具开发，前提是遵守适用法律），而且没有专门提到逆向工程或 DRM。该政策新版的生效日期是 2026-11-12（[Anthropic AUP](https://www.anthropic.com/legal/aup)）。

### 它不是沙箱，还会执行目标

SECURITY.md 写得很清楚："This is not a sandbox… Opening an untrusted binary delegates parsing and analysis to the selected local provider with that user's permissions."（这不是沙箱……打开不可信的二进制文件，就是以用户权限把解析和分析交给所选的本地引擎）（[SECURITY.md:33-36](https://github.com/morluto/rea/blob/b2257653ca74e1013553d5bd916a0ef85a3c7678/SECURITY.md#L33)）。HEAD 的 207 个工具里，有 82 个会启动进程，58 个会访问网络，46 个会写文件，**15 个会执行外部代码**（进程场景捕获、Frida、gdb/Rizin 调试、浏览器和 Electron 场景捕获等），**6 个会改动 Android 设备**（安装或卸载 APK、推送文件等）（[toolEffects.ts](https://github.com/morluto/rea/blob/b2257653ca74e1013553d5bd916a0ef85a3c7678/src/contracts/toolEffects.ts#L55)）。Frida 脚本"execute inside the selected target with that process's memory, filesystem, and network authority"（在目标进程内部执行，拥有该进程的内存、文件系统和网络权限）（[frida-instrumentation.md:11](https://github.com/morluto/rea/blob/b2257653ca74e1013553d5bd916a0ef85a3c7678/docs/frida-instrumentation.md#L11)）。提示注入是另一个实际风险：目标程序里的字符串可以伪装成给代理的指令。REA 的服务器指令要求代理把所有目标内容当数据，遇到"运行、安装、下载、发送"之类的请求一律视为注入并报告；除两个工具外，所有结果都带 `_meta.provenance.untrusted_content` 标记（[createServer.ts:147](https://github.com/morluto/rea/blob/b2257653ca74e1013553d5bd916a0ef85a3c7678/src/server/createServer.ts#L147)、[mcp-contracts.md:151](https://github.com/morluto/rea/blob/b2257653ca74e1013553d5bd916a0ef85a3c7678/docs/mcp-contracts.md#L151)）。但这个标记只是建议性的，能不能真正拦住，要看宿主程序和模型本身是否遵守；官方也承认，直接读 Kuna 的导出文件会绕过这个标记（[kuna-provider.md:53](https://github.com/morluto/rea/blob/b2257653ca74e1013553d5bd916a0ef85a3c7678/docs/kuna-provider.md#L53)）。学界已有论文专门研究如何在二进制中植入提示注入、误导 AI 逆向代理（[arXiv 2605.30677](https://arxiv.org/pdf/2605.30677)、[arXiv 2607.12507](https://arxiv.org/pdf/2607.12507)）。供应链方面，好的一面是：发布版没有 install 脚本，39 个生产依赖全部锁定到确切版本（HEAD 多了 `openpgp`，为 40 个），通过 GitHub Actions 可信发布并带 SLSA 来源证明，注册时也锁定版本。需要留意的一面是：npm 上只有一位维护者；三个月发了 32 个版本、6 个主版本，安全修复只覆盖最新版；文档里的 `curl | bash` 安装方式取自 `main` 分支；Windows 预编译 `.node` 插件不在 git 仓库里；Linux 上安装 Hopper 会通过 `pkexec` 以 root 执行包管理器；HEAD 已经加了 PGP 签名校验，但 SECURITY.md 仍写的是 SHA-1 校验，已发布的 6.5.0 也还没带 `openpgp` 依赖（[SECURITY.md:50](https://github.com/morluto/rea/blob/b2257653ca74e1013553d5bd916a0ef85a3c7678/SECURITY.md#L50)）。此外已经出现了冒名仓库，例如提供 Windows zip"官方免费下载"的 `rea-githu/REA`，有报道称某个假仓库带有被 Microsoft Defender 拦截的木马（二手）（[rea-githu/REA](https://github.com/rea-githu/REA)、[pasqualepillitteri.it](https://pasqualepillitteri.it/en/news/23845/rea-reverse-engineer-anything-github-true-false)）。官方 README 特别提醒，只认 morluto/rea、rea.tools 和 npm 上的 rea-agents 三个来源（[README.md:29-33](https://github.com/morluto/rea/blob/b2257653ca74e1013553d5bd916a0ef85a3c7678/README.md#L29)）。

## 谁该用、怎么安全地试、开发者如何自保

### 最适合会读汇编、又想省掉体力活的人

从官方案例和独立实测看，REA 的甜区在以下几类场景：资安研究和恶意样本的静态初筛，Evidence 记录能把观察和推论分开；CTF 和逆向教学，官方案例就是 DownUnderCTF 2023 的一道入门题（[ctf-masked-squares.md](https://github.com/morluto/rea/blob/b2257653ca74e1013553d5bd916a0ef85a3c7678/website/evidence/ctf-masked-squares.md)）；开发者审计自己的或开源的 Electron、JavaScript、.NET 应用，这是 REA 最成熟、自研代码最多的部分；为互通性或软件保存去研究老旧、停更的程序；以及想弄清楚自己电脑上某个软件到底在做什么的隐私审计。它不适合三种期待：想拆强保护的商业软件；以 Windows 原生程序为主却不想折腾 Ghidra 和 Java 版本；指望"一句话克隆整个应用"。掘金的评论说，REA 对新手帮助最大，对中级逆向工程师的冲击最大（[掘金](https://juejin.cn/post/7695958498477211675)），这一点和本报告的证据是一致的。

### 安全试用：隔离环境、收紧权限、管住数据

安全试用的第一步是**隔离环境**：在可以快照回滚的虚拟机或专用操作系统账号里运行 REA、引擎和代理，不要放在存有 SSH 密钥、云端凭证或公司源码的日常账号里。分析来路不明的样本时，还要限制出网，因为静态分析本身就会以你的权限解析文件，运行时工具更会真正执行它（DISCLAIMER 也要求"use an appropriate environment for untrusted targets"，即对不可信目标使用合适的环境）（[DISCLAIMER.md:54-55](https://github.com/morluto/rea/blob/b2257653ca74e1013553d5bd916a0ef85a3c7678/DISCLAIMER.md#L54)）。第二步是**固定版本、来源可验**：优先用 `npm install --global rea-agents@<确切版本>`，用 `npm audit signatures` 校验来源证明；不需要 Frida 就加 `--omit=optional`；不要从 `main` 分支执行 `curl | bash`；`rea setup` 先用 `--dry-run` 看清计划，用不到 Hopper 就拒绝安装，也就避开了唯一一个需要 root 的步骤（[install.sh](https://github.com/morluto/rea/blob/b2257653ca74e1013553d5bd916a0ef85a3c7678/install.sh#L141)）。第三步是**收紧代理权限**：不要用"全部允许"或绕过审批的模式。会执行外部代码或改动设备的工具（`capture_*_scenario`、Frida 系列、`gdb_console`、`execute_rizin_command`、`install_adb_package` 等）要逐次审批；只读的静态工具（`analyze_function`、`procedure_*`、`read_bytes`、`analyze_javascript_application`）风险最低，适合先上手。REA 的结果在上下文里时，代理的 shell、网络和写文件权限都应保持在"询问"状态，也可以写 hook，读到 `untrusted_content` 标记后提高审批强度。注意 setup 默认是**全局注册**（例如写进 `~/.claude.json`），会让每个项目都多出上百个工具和大量上下文开销，用完可以执行 `rea uninstall --purge-data` 清掉（[installation.md:155-162](https://github.com/morluto/rea/blob/b2257653ca74e1013553d5bd916a0ef85a3c7678/docs/installation.md#L155)）。第四步是**管住数据**：只分析自己的、开源的或获得书面授权的软件；客户软件和受 NDA 约束的二进制，不要通过消费版账号送进云端模型，改用商业条款或 ZDR 方案，或者用支持本地 MCP 的客户端接本地模型；用消费版时记得关闭"用于改进模型"的选项，并定期清理本机明文对话记录。最后，**只从官方三个来源下载**。

### 担心自家软件被 AI 逆向的开发者能做什么

最有效的一招，和 Bachaalany 给的建议、和 REA 自己承认的边界是同一件事：**把关键逻辑、授权校验和秘密放在服务器端**。第三方研究仓库的说法是，"服务端逻辑（agent 够不到服务器）"仍在保护软件厂商，而"客户端功能逻辑的'隐性保密'贬值"，壁垒转向服务端、网络效应、品牌与执行速度（[ringozzt/rea-research](https://github.com/ringozzt/rea-research)），护城河"只是在搬家"（[什么值得买](https://post.smzdm.com/p/awwo5q6p/)）。第二，**默认客户端代码会被读懂**：前面 .NET 实测 1.5 秒就读出了内嵌的上传密钥，所以 API 密钥绝不能硬编码进客户端；生产环境不要发布 source map（REA 会专门解析它）；原生程序发布前去掉符号；Electron 要明白 ASAR 只是打包格式，不是保护，应该开启 Electron fuses、收窄 preload 和 IPC 的暴露面（REA 自己就有 `inspect_electron_fuses` 工具来检查这些）。第三，**混淆和虚拟化能抬高成本，但不是城墙**：VMP 这类强保护目前确实挡住了 AI（见上文），Quarkslab 也指出现代混淆能让 AI 产出"看似结构正确、实则不反映真实行为"的反编译结果（[Quarkslab](https://blog.quarkslab.com/defeating-ai-assisted-reverse-engineering-or-at-least-trying-to.html)），但付出的是性能、调试难度和兼容性。第四，**用合同和法律补位**：EULA 里的禁止逆向条款在美国通常可以执行，在欧盟不能排除为互通性而做的反编译；保留开发过程和著作权证据，发现克隆时才能主张权利。第五，**先拿 REA 拆自己**：用它对自家产品做一次红队演练，看看 AI 代理能看到什么，比任何猜测都准。长远看，真正的护城河会转向数据、服务、网络效应和迭代速度，因为可以观察到的功能实现正在更快地失去稀缺性（[53AI](https://www.53ai.com/news/LargeLanguageModel/2026101359802.html)）。

## 解放还是抄袭：答案取决于拿它做什么

先替两种立场各找最强的论据。说它"解放软件"的一方可以举出：REA 官方列出的用途几乎全属正当（资安、互通、保存、教育）；它的标志性案例是 1996 年的 DX-Ball 和 PC-98 时代的东方 Project 旧作（TH04）这类保存型重建；它不提供破解加壳或虚拟化保护的工作流、碰不到服务器，政策上也拒绝帮人破解；而且它把原本只属于少数专家的"看懂软件在做什么"的能力，交给了安全研究者、学生和普通用户。说它"帮人抄软件"的一方同样有据：README 的第一句推介就是"See a feature in an app that you want in your own product? Ask your agent to investigate it with REA… and build a version for your project."（在别人的应用里看到想要的功能？让代理用 REA 去研究……然后为你的项目做一个版本）（[README.md:61](https://github.com/morluto/rea/blob/b2257653ca74e1013553d5bd916a0ef85a3c7678/README.md#L61)），这和 DISCLAIMER 里"不协助复制专有软件"的承诺之间存在明显张力；代码里没有任何技术护栏；生态里已经有整部游戏逐字节重建并发布可玩版本的先例；媒体也报道了 GTA 5、Halo 被 AI 逆向工具移植到浏览器的事件（[Startup Fortune](https://startupfortune.com/ai-reverse-engineering-turns-gta-5-and-halo-into-browser-games-overnight/)，是否用了 REA 未经核实），17173 甚至写出"80、90 后经历过的那个盗版年代好像又要重回了"（[17173](https://news.17173.com/content/10152026/020057361.shtml)）。

综合证据，本报告的判断是：**REA 本身是一把典型的双刃工具，但它在两边改变的东西不对称。** 在"解放"这一边，它真正降低了理解未加保护的客户端软件的成本，这种理解在多数法域本来就合法（思想与表达二分、互通性例外、反向工程不算侵犯商业秘密），只是过去要付出专家级的时间。在"抄袭"这一边，它降低的主要是**模仿功能**的成本，而模仿功能（不复制代码）一直是合法竞争；它并没有让**复制代码表达**变得更合法，也没有让这种行为更容易免责：AI 读过反编译代码之后的"重写"很难主张净室开发，分析输出也不带来任何权利，规避保护措施在各法域都要承担责任。帖子把问题设成二选一，其实答案取决于使用者：拿 REA 去理解、审计、对接、保存，就是在"解放"；拿它去搬运反编译出来的实现、绕过授权、做出替代原作的克隆，就是在"抄"，而且法律风险落在使用者身上，不在工具身上。真正受冲击的，是那些把商业价值押在"客户端代码看不懂"上的软件，以及中级逆向从业者的体力活；强保护程序和服务器端的业务逻辑，至少目前还不在其中。

## 结论

这次核查最值得记住的发现，是**项目自己的证据档比它的传播版本诚实得多**。REA 仓库里的每个示范都附了哈希、工具版本，以及"分析师辅助""示意提示词""仅限此函数"这类限定语；到了媒体和社交平台上，这些限定语几乎全被删掉，只剩"3,205""63 字节""26 万星"这些数字。对读者来说，比起问"帖子的数字对不对"，更有用的是问"这些数字的分母是什么"：一个 23 条指令的函数，一个早已开源的计算器规则，一个只代表关注度、不代表使用量的星数。这个方法同样适用于今后任何"AI 能做 X"的爆款叙事。

更深一层的变化是**逆向的经济学**。REA 和同类工具没有改变技术上可以做到的事，但把"看懂客户端软件"的边际成本压到了接近一次对话的价格。软件保护的重心会因此加速转向服务器端、合同和法律；"客户端代码看不懂"不能再当作商业秘密的保护手段。接下来值得关注四件事：Hex-Rays 官方 MCP 等引擎厂商自己下场之后，REA 这类编排层还剩多少空间；模型商会不会针对逆向用途收紧政策；美国第十轮 §1201 豁免规则制定（豁免期 2027–2030）会如何处理 AI 辅助的研究（[U.S. Copyright Office](https://www.copyright.gov/1201/2027/)）；以及第一起认定"AI 辅助反编译后重写"是否算净室开发的诉讼。
